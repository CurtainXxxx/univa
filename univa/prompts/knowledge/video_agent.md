# UniVA 视频 Agent 领域知识库

> 每条 `##` 段是一条可被 Global Memory 检索的知识。
> 内容来自实测经验（API 约束、工具特性、评测教训）。

## 长视频编辑必须分片
云端 VACE 模型单次推理上限约 5 秒。编辑长于 5 秒的视频时，必须先切成 ≤5s 片段逐片编辑，再用 ffmpeg 按时间轴合并回完整视频。失败片段用原片顶替，保证输出时长完整。

## 视频编辑工具选择
风格迁移、重绘用 style_transfer（VACE inpainting）；只改前景/背景用 depth_modify；换物体外观用 repainting。这些工具每次调用有成本，能一步完成就不要拆多步。

## 视频理解要抽帧
视觉大模型不能直接看视频，需要抽帧。64 帧均匀采样能在质量与成本间取得平衡；少于 32 帧会损失细节，超过 128 帧会超过接口限制并增加成本。

## 文生视频 prompt 用英文
Wavespeed 系列生成模型对英文 prompt 的遵循度明显好于中文。中文请求先翻译成英文描述再生成，视频内容更贴合。

## 实体一致性用参考图
多图故事或实体转视频时，必须用用户提供的参考图片作为角色锚点，保持身份一致。不要相信模型编造的图片路径，只使用真实存在的输入图。

## 避免重复生成
视频生成成本高。同一个生成任务只提交一次，收到结果后如实记录路径，不要重复调用工具。重复提交会造成双倍扣费。

## 文本转视频优先原子工具
长文本转视频直接用 text2video_gen。只有用户明确要求多角色、多镜头的故事视频时，才用 storyvideo_gen/entity2video（成本更高）。

## 视频到视频的度量
编辑/转换类任务用 DINO 衡量与原视频的内容保留度，用 CLIP 衡量与指令的语义对齐。两者一高一低组合说明"编辑生效且不过度"。

## 规划要控制步骤数
一个用户请求的计划步骤越少越好，最多不超过 5 步。能用单个原子工具完成的，绝不要拆成多个步骤或添加冗余的延长/扩展调用。

## 接口的输入限制
每次工具调用输入材料有数量限制（如一次一张参考图）。多个材料需要多次调用，每次单独一个 step，并在 input_requirements 里写清路径。
